## 4. Credits（W4）

credits 分三層，全部自動產生，不手動維護名單：

| 層 | 來源 | 呈現 |
|---|---|---|
| 網站製作 | 本 repo 的 git commit 作者（GitHub API `contributors`）＋ `content/credits.yml` 中的非程式貢獻角色（Logo：Sun、文案：品毅…） | Owner、Collab、各角色、commit 貢獻者頭像 |
| 組織文件 | mono 各文件末尾的「資訊貢獻者」段落 | 每份文件的貢獻者清單 |
| 社群 | mono 的 git commit 作者、`Members/` 自介作者 | 頭像牆 |

`content/credits.yml` 範例：

```yaml
website:
  owner: [ray-github]
  collab: [kun-github, sun-github, yayapipi-github]
roles:
  - role: Logo
    people: [sun-github]
  - role: 文案
    people: [pinyi-github]
```

非程式貢獻（設計、文案、討論）不會出現在 git 紀錄中，所以需要這份檔案；每次有人修文案或設計，PR 中順手加上自己即可。GitHub 帳號待大家提供。

## 5. 技術要點（V1）

- 文案在 `src/content/zh/*.md`、`src/content/en/*.md`，元件只讀取，不寫死文字。
- 所有外部連結（Discord 邀請、mono 文件、活動串）集中在 `src/config/links.ts`；Threads SOP 改連結時只改一處。
- 第一天就開 `/en/` 路由（擴充性 E3）。
- Cloudflare Workers 部署，每個 PR 有預覽網址，方便大家一起修文案與視覺。
- 上線前檢查：Lighthouse、連結檢查、OG 圖、憲法逐條檢查。

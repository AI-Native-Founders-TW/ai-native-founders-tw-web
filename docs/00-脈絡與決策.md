## 3. 由此修正的三個判斷

1. **V1 不是資源站，是 vision 站。** 會議的方向是先把 problem 講清楚，讓大家願意參與。品毅希望內容有料，這項需求放到知識庫階段，V1 用「我們想整理的流派」預告，不假裝已經完成。
2. **credits 從第一版就要有。** 這是拍板決策（W4），也是會議中志工貢獻的誘因設計。
3. **文案必須可以由非工程師修改。** W2 明定大家一起修文案；文案放在 Markdown／YAML，元件只負責呈現。

## 4. 需要注意的界線

| 議題 | 風險 | 處理 |
|---|---|---|
| 成員產品展示（Sun 的需求） | 憲法第 7 條：不得用組織名義為特定公司推銷 | 成員卡片只放本人自介中寫的「我在做什麼」與連結，不做精選、排名或推薦版位；是否有專區先交給團隊拍板 |
| 配對、引薦、mentor、batch | 都在 Note 未採納 | 網站不寫成已提供的服務 |
| Weekly Online Meeting、月度聚餐 | 是有平的候選做法，頻率未決 | 有實際活動才放進活動頁，不寫成固定制度 |
| 只收軟體還是 widely open | 未表決（信任、賽道兩層漏斗） | 網站不寫賽道限制；只寫「看真誠，不看背景」 |
| Discord 是否必要 | 逐字稿前後說法不一，文件以 mono 申請制度為準：Discord 會邀請，但不是入會門檻 | 依 mono 申請制度的寫法 |

# 設計方向：獎項等級的首頁

> 目標：首頁做到 Awwwards Site of the Day／FWA 等級（網頁界最接近紅點的標竿），同時不失去組織的調性：歡迎、誠實、不菁英。視覺最終由 Sun 拍板。

## 1. 得獎網站的共通點

得獎靠的不是特效多，而是：

1. **一個強烈、獨特的概念**，整頁都服務它。
2. **用捲動說故事**：每一段都有節奏、有轉場、有記憶點。
3. **細節工藝**：字體排版、微互動、載入、游標、轉場、404 頁都有設計。
4. **效能與無障礙**：評審會在手機上看；卡頓會直接扣分。

## 2. 核心概念：「Speedrun」

逐字稿中水球把這個組織比喻成 speedrun，把創業路線比喻成《流亡黯道》的流派（0:31、0:58）。組織名稱裡本來就有 Speedrun。**整個首頁就是一場 run**：訪客往下捲動，就是在跑這場 run。

### 貫穿全頁的三個元素

| 元素 | 說明 |
|---|---|
| **Speedrun 計時器** | 角落的 HUD 顯示計時與 splits（分段時間），每個章節就是一個 split。這是整站的招牌記憶點 |
| **光點（Logo 的圓點）** | Logo 右上的圓點代表「你」。它跟著游標移動，在章節之間穿梭，最後落在「提交自介」的終點 |
| **A 字光帶** | Logo 的 A 以 WebGL 光帶呈現，顏色流動取自 Logo 漸層，在各章節變形成路線、樹狀圖等 |

## 3. 章節分鏡

| Split | 章節 | 畫面與互動 | 要傳達的事 |
|---|---|---|---|
| 00 | **載入** | 光點從黑暗中出現，畫出 A 字；計時器歸零、開跑 | 品牌第一印象 |
| 01 | **Hero** | 全螢幕 WebGL 光帶隨游標流動；標語逐字浮現：「用一份筆記槓桿全台創業者的認知」 | 我們是誰 |
| 02 | **重複的 coffee chat** | 畫面上數十個重複的對話泡泡，捲動時收攏成一份筆記，再分享給上百個光點 | 一次分享，幫到很多人（先成立媒體，再請求幫助） |
| 03 | **從台灣出海** | 光帶在捲動中從台灣畫一條路線到舊金山，途中標出關卡：開公司、資本額、Funding Plan、Culture Fit | 出海之路與認知落差 |
| 04 | **流派技能樹** ★ | 仿《流亡黯道》天賦樹的星圖：流派是一群群節點，滑過節點展開流派卡（適合誰／前期成本／辛苦程度）；流派卡誠實標示「整理中」與「範例」 | 攻略與流派，這是招牌互動 |
| 05 | **選擇你的起點** | 遊戲的角色選擇畫面：學生／剛當 PM／還在上班／正在創業／矽谷前輩。選了之後，下方文案換成對應的話 | 你不需要準備好（減少菁英主義） |
| 06 | **AI-Native** | 同一座台灣分成組織本身、產品本身、產品的設計和開發三層，鏡頭依序走過三層，一條光線貫穿後拉開到台灣與全球 | 名字裡 AI-Native 的三層含義，以及讓台灣持續輸出 AI-Native founders 的願景 |
| 07 | **我們不做什麼** | 安靜的一段：大字、留白、停止動效 | 不收入會費、不推銷、不收錢置入（節奏放慢，讓人信任） |
| 08 | **終點線：加入** | 四個檢查點（Discord → Star → 閱讀 → 提交自介），光點抵達終點；計時器停下，顯示「你的 run 從這裡開始」 | 主要轉換：提交自介 PR |
| 09 | **Credits Roll** ★ | 像遊戲破關後的工作人員名單，所有貢獻者的頭像與角色往上捲動；可以暫停、點擊進入個人頁 | W4 明確標注大家的 credits |

★ 是投稿時最能被記住的兩個作品。

### 調性的界線

- 炫但溫暖：用遊戲語言和真實的人（成員頭像、本人的話），不用奢華、冷硬的科技感。
- 誠實：技能樹和流派卡標示「整理中」，AI 展示標示「示範」，不假裝已經有完整服務。
- 不做排行榜、積分、等級，避免變成參與壓力（憲法第 13 條）。

## 4. 技術做法

架構不變（見[架構與技術棧 v2](./02-架構與技術棧.md)），首頁多一層「體驗層」：

| 層 | 做法 |
|---|---|
| **內容層**（一定要先有） | 所有文字都是真正的 HTML，由 Astro 靜態輸出；沒有 JS 也能讀完整頁、SEO 不受影響 |
| **體驗層**（漸進增強） | 首屏內容出現後才載入 WebGL 與動效；依裝置效能分級 |

| 用途 | 選擇 | 版本 |
|---|---|---|
| 捲動編排、文字動畫 | **GSAP**（ScrollTrigger、SplitText、MorphSVG） | 3.15，現在包含外掛在內都免費 |
| 平滑捲動 | **Lenis** | 1.3 |
| WebGL | **Three.js**＋自寫 GLSL shader（光帶、粒子） | 0.186 |
| 效能分級 | detect-gpu | 5.0 |
| 技能樹 | SVG＋GSAP（節點少於 200 個時不需要 Canvas） | — |
| 簡單的捲動效果 | CSS scroll-driven animations | — |
| 頁面轉場 | Astro View Transitions | — |
| 3D 素材（如需要） | Blender → glTF（Draco 壓縮） | — |

程式結構：每個章節是一個獨立元件（`src/experience/chapters/0X-*.astro`＋對應的 island），共用一個捲動控制器與一個 WebGL canvas。**一個章節可以由一個人認領**，Kun、Sun、Yapi 可以平行開發，也符合組織「誰 care 誰 own」的分工。

### 效能與無障礙預算

| 項目 | 目標 |
|---|---|
| LCP（手機 4G） | < 2.0 秒（Hero 標語是 HTML，不是 canvas） |
| 首頁 JS（gzip，不含延遲載入的 Three.js） | < 120 KB |
| 動畫 | 中階手機 60fps；低階裝置自動改用 CSS 漸層靜態版 |
| `prefers-reduced-motion` | 關掉捲動編排與 WebGL，保留全部內容 |
| 跳過動畫 | 右上角提供「跳過 run」，直接到加入區 |
| 中文字型 | 標題字只子集化用到的字，避免下載數 MB 的字型檔 |
| 手機版 | 每個章節另外設計手機的編排，不只是縮小 |

## 5. 怎麼做出來（流程）

| 步驟 | 產出 | 誰 |
|---|---|---|
| 1. 情緒板 | 30–50 個參考（Awwwards、Godly、Mobbin…），依「概念、轉場、字體、互動」分類 | Ray＋AI（在內建瀏覽器收集截圖） |
| 2. 概念與分鏡 | 本文件第 3 節定稿；每個章節的捲動分鏡（Figma） | Ray、Sun |
| 3. 美術方向 | 字體、色彩、光帶與光點的樣式、動態原則（速度、緩動曲線） | Sun 拍板 |
| 4. 技術原型 | 先做三個風險最高的：Hero shader、技能樹、Credits Roll | Ray、Kun |
| 5. 分章節開發 | 每章一個 PR、各自有預覽網址 | 認領的人 |
| 6. 打磨 | 微互動、游標、載入、404、音效（預設關閉） | 全員 |
| 7. 測試 | 實機（iPhone、中階 Android）、效能、無障礙 | 全員 |
| 8. 投稿（選擇性） | Awwwards、CSS Design Awards、FWA；紅點（Brands & Communication Design）報名費不低，需要先確認經費 | 團隊拍板 |

## 6. 時程的取捨

水球想在 Landing Page 上線後發第二波招募，不能讓獎項等級的首頁拖住上線。建議分兩次上線：

| 版本 | 內容 | 目的 |
|---|---|---|
| **Launch** | 內容層完整＋Hero 光帶＋計時器 HUD＋終點線＋Credits Roll | 先撐起第二波招募，已經有招牌記憶點 |
| **Award Edition** | 補上 coffee chat 收攏、出海路線、技能樹、角色選擇、AI 展示，再加上整體打磨 | 投稿用；每完成一章就上線一章 |

## 7. 需要大家提供的

1. Sun：Logo SVG（光帶與光點要能拆開）、美術方向確認。
2. 品毅：每章 1–2 句的主文案，中文要短，才撐得住大字排版。
3. 全員：GitHub 帳號與頭像使用同意（Credits Roll、AI 展示會用到）。
4. Mobbin 帳號（在內建瀏覽器登入），或改用免費的參考網站收集情緒板。

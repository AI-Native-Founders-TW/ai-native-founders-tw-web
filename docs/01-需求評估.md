# 需求評估

> 依據：[ai-native-founders-tw-mono](https://github.com/AI-Native-Founders-TW/ai-native-founders-tw-mono) 的 vision、憲法、申請制度、志工協作工作流，以及 2026-10-24 第一次核心會議（A5 Landing Page：Ray；kun 協作／A11 Domain：水球／A12 UIUX：Sun／A13 文案：品毅）。

## 1. 網站要解決的 Problem（對回 mono specs）

| # | Problem（mono 出處） | 網站能做的事 |
|---|---|---|
| P1 | 封閉感重、還沒準備好的人不覺得自己是受眾（vision「封閉感是有點重」） | 首頁語氣與文案明確傳達「沒經歷、還在探索也歡迎」，不呈現菁英、募資導向的形象 |
| P2 | 每人重做 coffee chat、前輩時間效益有限（vision「出海創業之路該怎麼進行」、Principle「先成立媒體，再請求幫助」） | 對外的「媒體門面」：讓矽谷前輩看得懂這是什麼、一次分享能幫到多少人（需英文版） |
| P3 | 加入申請的處理成本（工作流的「我們能不能減少我們的營運成本」） | 把加入流程講清楚、降低 PR 門檻（自介產生器，見 F5），減少客服重複回答 |
| P4 | 找人幫忙得一個一個問（工作流「找人幫忙時，得一個一個去問」） | 成員目錄：把 `Members/` 自介的 R&R 變成可搜尋、可篩選的頁面 |
| P5 | 資訊量太多、新人不知從何讀起（工作流「會不會有可能也是會變成資訊量太多」） | 知識庫入口：依情境／流派導覽筆記，並提供站內搜尋 |
| P6 | 貢獻要留下 credit（憲法第 10 條、工作流） | 每篇筆記與頁面自動列出資訊貢獻者 |

## 2. 必須遵守的約束（憲法 → 網站規則）

| 憲法 | 對網站的硬約束 |
|---|---|
| 第 2、7、9 條 非營利、不推銷、不收費置入 | 不做付費贊助版位、不放廣告、不放特定公司產品推薦；合作單位僅以「合作」形式呈現且不收費 |
| 第 10 條 資訊貢獻者署名 | 筆記頁一定要有貢獻者區塊，資料來源為 mono，不在網站另存 |
| 第 11、12 條 加入只看意圖、依申請制度 | 網站**不能**另設表單當作入會途徑；唯一入口是自介 PR。不可寫出背景／實力門檻 |
| 第 13、14 條 志工不強制 | 成員目錄的 R&R 只呈現「本人表達的意願」，文案不能暗示「已承諾幫忙」 |
| 第 17 條 開放 | 所有知識內容免登入、可公開存取、可被搜尋引擎與 AI 讀取 |
| mono AGENTS.md：Plan 不是規格，不另存第二份可編輯的 truth | 網站內容**一律從 mono 讀取**；網站 repo 只放呈現層與少量行銷文案 |
| Note 內容未採納 | 配對系統、mentor 制度、batch、Skill/MCP 等 Note 構想，網站不得當成已提供的服務寫出 |

## 3. 使用者與使用意圖

| 角色 | 主要意圖 | 對應功能 |
|---|---|---|
| 想探索創業的人（學生、PM、上班族） | 「這是什麼？我適合嗎？怎麼加入？」 | F1、F2、F5 |
| 正在創業／想出海的 founder | 找攻略、找同伴、找能幫忙的人 | F4、F6 |
| 矽谷前輩、VC、國際 founder | 「這組織是誰？我分享能帶來什麼？怎麼聯繫？」 | F1（英文）、F7 |
| 既有成員／志工 | 找人協作、看活動、更新自己資料 | F3、F4 |
| 合作社群、媒體 | 認識組織、取得素材 | F1、F7 |

## 4. 功能清單與優先序

### MVP（Landing Page，對應 A5）

- **F1 首頁**：一句話定位（「用一份筆記槓桿全台創業者的認知」）、我們想改變什麼、價值主張（憲法第 3 條五點）、我們不做什麼（非營利／不推銷）、CTA。
- **F2 如何加入**：四步驟（加入 Discord → Star Repo → 閱讀創辦人的話／憲法／申請制度 → 提交自介 PR），內容與 Threads SOP 公版一致；FAQ（「沒經歷能加入嗎？」「Discord 是門檻嗎？」「AI 寫自介可以嗎？」）。
- **F3 活動**：目前的活動（例：「想問矽谷大佬關於創業出海的問題」）連到 Discord；MVP 先手動維護清單。
- **F10 Credits**（Discord 決策 W4，V1 必備）：網站與組織貢獻者自動產生，含非程式貢獻（Logo、文案）。詳見 [V1 範圍與內容 §4](./06-V1範圍與內容.md#4-creditsw4)。
- **F8 基礎**：zh-TW 為主、SEO／OG 圖、RWD、無障礙、`llms.txt`。

### Phase 2

- **F4 成員目錄**：解析 `Members/*.md`，卡片顯示名稱、我是誰、可以幫什麼忙、想要幫什麼忙；全文搜尋與關鍵字篩選。
- **F5 自介產生器**：表單引導填寫範本欄位 → 預覽 → 一鍵開啟 GitHub 網頁編輯器（自動 fork、預填 `Members/<帳號>.md`）建立 PR。全程無後端、不收集資料，仍以 PR 為唯一申請途徑。
- **F7 組織文件**：渲染願景、創辦人的話、憲法、制度；英文版首頁。
- **F9 分享紀錄與影響力**：前輩分享／AMA 的成果頁（整理成哪些筆記、署名誰），以及筆記數、貢獻者數、成員數等數據，讓前輩看見時間的效益（vision「先成立媒體，再請求幫助」）。詳見[擴充性](./04-擴充性.md)。

### Phase 3

- **F6 知識庫（攻略與流派）**：依 Founder-Market Fit／團隊組合／產業等維度導覽筆記；站內搜尋；每篇列貢獻者。前提是 mono 先有筆記內容與分類方式。
- 機器可讀輸出：`llms.txt`、`llms-full.txt`、JSON feed，讓 AI 能拿到 context（不宣稱提供 Skill/MCP 服務）。

### Backlog（Note 中未採納，需先在 mono 拍板）

- 配對推薦（Jasmine 提案）、mentor／batch 頁、Discord 活動自動同步、電子報、多地區實體活動頁。

## 5. 非功能需求

- **零營運成本**：組織沒有資金 → 靜態網站、免費託管、無資料庫、無登入。
- **好協作**：志工時間零碎 → 任何人改 Markdown 開 PR 即可，PR 自動產生預覽網址。
- **單一事實來源**：mono 更新後網站自動重建。
- **雙語**：zh-TW 為主，英文給矽谷前輩（Phase 2）。
- **效能／SEO**：Lighthouse 95+；中文字型子集化。

## 6. 待團隊確認的問題

1. **網域**：`ainative.tw` 是否 Donate、是否改成含 Founders 的名稱（A11 水球）。
2. **託管帳號**：用組織名下的 Cloudflare 帳號還是 GitHub Pages？誰持有？
3. **成員判定**：自介檔案已合併進 `main` 是否就視為「審查通過的成員」？（自介審查 TODO 尚未定案，網站在此之前可標示為「自介」而非「成員」。）
4. **英文版**的優先度與翻譯負責人。
5. **品牌**：Logo、色彩、字型由 Sun 定義？
6. **repo 位置**：本專案作為 `AI-Native-Founders-TW/` 下獨立 repo，再以 submodule 掛進 mono（D6、A6 權限）。

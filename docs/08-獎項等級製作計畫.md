# 獎項等級製作計畫

> 接續[設計方向](./07-設計方向.md)的「Speedrun」概念，回答三件事：做不做得到、動態怎麼做（程式動畫、Motion Design、Seedance 2.5）、要多少人力、時間和錢。

## 1. 結論

**做得到，但決定成敗的是美術方向和打磨時間，不是技術。** 技術上，捲動敘事、視差、WebGL、AI 生成影片都已經成熟，而且大部分免費。真正的風險有三個：

1. **美術方向**：要有一個人（Sun）對每一格畫面拍板，維持一致的風格。
2. **打磨時間**：得獎網站有一半的時間花在最後 10% 的細節上。
3. **志工時間**：用「先上線、再分章節升級」的方式，避免全部卡在一起。

## 2. 評審看什麼 → 我們怎麼對應

Awwwards 以 Design 40%、Usability 30%、Creativity 20%、Content 10% 評分；紅點（Brands & Communication Design）同樣重視創新、功能、美感與品牌一致性。

| 評審面向 | 我們的對策 |
|---|---|
| Design（美感、一致性） | Logo 漸層延伸成整套視覺語言；字體、色彩、動態曲線全部 token 化 |
| Usability（手機、效能、無障礙） | 手機另外編排分鏡；效能預算；減少動態模式；「跳過 run」 |
| Creativity（概念） | Speedrun 計時器、流派技能樹、Credits Roll：別人沒有、只屬於這個組織的概念 |
| Content（內容與故事） | 文案來自真實會議與真實成員，不是行銷空話 |

## 3. 參考（Mobbin）

Mobbin 的「Scroll Effects」風格共有 127 個網站，先從這些開始建情緒板：

- **Shopify Editions**（3D、捲動效果）：章節式的捲動敘事
- **Daylight**、**Zipline**：用捲動推進產品故事
- **Unseen Studio**、**TinyWins**：動態與品牌感很強的工作室網站
- **Tempo**、**Museum of the Human Web**：深色、有質感的資訊呈現

篩選網址：`https://mobbin.com/search/sites?content_type=sites&filter=styles.Scroll+Effects`。另外值得一起看的風格標籤有 Motion、Dark、3D。

目前內建瀏覽器的截圖功能無法使用，情緒板需要讓分頁保持在畫面上再重試，或由人手動在 Mobbin 收藏到同一個 Collection。

## 4. 動態策略：三種做法，各用在最擅長的地方

| 做法 | 工具 | 擅長 | 不擅長 |
|---|---|---|---|
| **A. 即時程式動畫** | GSAP（ScrollTrigger、SplitText）、Lenis、Three.js shader、Motion（React 元件的微互動） | 跟著捲動與游標即時反應、文字動畫、資料驅動（成員、貢獻者） | 寫實、電影感的畫面 |
| **B. 互動向量動畫（Motion Design）** | **Rive**（帶狀態機的互動動畫，檔案很小）；或 After Effects → Lottie | 角色、吉祥物、按鈕與圖示的狀態變化 | 大面積寫實場景 |
| **C. 預先渲染的電影感影片** | **Seedance 2.5**（AI 生成影片）；必要時用 Blender | 程式做不出來的畫面：光、空間、鏡頭運動 | 精準的 Logo、文字、互動 |

**原則：文字永遠是 HTML，影片和畫布只負責畫面。** AI 影片裡不要出現文字，也不要依賴它畫出精準的 Logo。

### 每個章節用哪一種

| Split | 章節 | 主要做法 | 說明 |
|---|---|---|---|
| 00 | 載入 | A | 光點畫出 A 字（SVG 路徑動畫＋shader 光暈） |
| 01 | Hero | A＋C | 背景是 Seedance 生成的深空光帶影片（循環播放）；前景是即時 shader 光帶，跟著游標流動；標語逐字浮現 |
| 02 | 重複的 coffee chat | A | 泡泡收攏成筆記，再分享給上百個光點：需要精準控制數量與節奏，用程式做 |
| 03 | 從台灣出海 | **C（捲動控制影片）**＋A | 招牌的電影感段落：光點從台灣夜空起飛、越過太平洋、在舊金山破曉；捲動控制影片進度；關卡名稱用 HTML 疊在上面 |
| 04 | 流派技能樹 | A | SVG 星圖＋GSAP；節點資料來自設定檔，之後由知識庫驅動 |
| 05 | 選擇你的起點 | B | 用 Rive 做五個角色剪影，選取時有狀態動畫 |
| 06 | AI-Native | A | 終端機打字動畫，在瀏覽器內比對公開自介 |
| 07 | 我們不做什麼 | — | 刻意不放動效 |
| 08 | 終點線 | A＋B | 光點衝線、計時器停下；Rive 做慶祝動畫 |
| 09 | Credits Roll | A | 資料驅動的工作人員名單 |

## 5. 捲動視差的四種技法

| 技法 | 用在哪 | 實作 |
|---|---|---|
| **多層視差** | Hero、各章節背景 | 前、中、後景分層，以 ScrollTrigger 設不同速度 |
| **2.5D 深度視差** | 出海章節的靜態畫面 | 用深度模型（如 Depth Anything）從單張圖產生深度圖，shader 依深度位移，單張圖就有立體感 |
| **固定場景＋捲動控制** | 章節 02、03、04 | 場景固定在畫面上，捲動只推進動畫進度 |
| **捲動控制影片** | 章節 03 | 影片轉成影格序列，在 canvas 上依捲動繪製（Apple 產品頁的做法）；捲動控制 `<video>` 的時間在 Safari 上不穩，所以用影格序列 |

## 6. Seedance 2.5 製作流程

Seedance 2.5 是 ByteDance 在 2026 年中推出的影片生成模型。第三方資料顯示可輸出 4K、單段最長 15–30 秒、支援多張參考圖；價格約每秒 0.10–1.10 美元，依供應商而定。規格與授權條款以官方或 API 供應商（如 Dreamina、fal）的頁面為準，**開工前要確認商業／公開使用條款**。

### 流程

1. **定調靜幀**：先用圖片模型生成 5–10 張關鍵畫面（Hero 光帶、台灣夜空、太平洋、舊金山破曉），色彩限制在 Logo 色票內；由 Sun 拍板。
2. **生成影片**：以拍板的靜幀當參考圖或起始畫面生成。每段的結尾畫面作為下一段的開頭，接起來就是一條連續的鏡頭。如果模型不支援指定結尾畫面，就在剪接時用光帶轉場遮住接縫。
3. **後製**：放大、調色（統一套 Logo 色票）、清掉 AI 雜訊與破綻、去除任何意外出現的文字。
4. **輸出**：
   - Hero 循環影片：AV1＋H.264 兩種格式，桌機 1080p 約 2–4 MB，手機 720p。
   - 出海章節：ffmpeg 抽成影格序列（桌機 1920 寬約 120 張、手機 960 寬約 60 張，WebP／AVIF），先載入低解析度，捲動到附近才換成高解析度。
5. **整合**：在 canvas 上依捲動播放；沒有 JS 或減少動態模式時顯示一張靜態代表畫面。

### 成本估算

| 項目 | 估算 |
|---|---|
| 成品總長度 | 約 40 秒（Hero 循環 8 秒＋出海 3 段×10 秒） |
| 生成次數 | 每秒成品約重生 10–20 次才挑得到好的 |
| 生成費用 | 約 40 秒 × 15 次 × 0.1–0.5 美元 ≈ **60–300 美元** |
| 其他 | 圖片模型、放大工具，多半有免費額度 |

組織沒有可動用的預算，**誰出這筆錢需要團隊拍板**，或先用免費額度與較低解析度做原型。

### 風險

| 風險 | 對策 |
|---|---|
| 鏡頭之間風格不一致 | 固定參考圖、固定色票、每次生成記下參數 |
| Logo 被畫歪 | 影片不出現 Logo；Logo 一律用 SVG 疊在上面 |
| 檔案太大拖慢手機 | 影格序列分段延遲載入；低階裝置只顯示靜態圖 |
| 授權不清 | 開工前確認條款；頁尾註明使用 AI 生成素材 |

## 7. 體驗引擎（技術架構補充）

延續[架構 v2](./02-架構與技術棧.md)，首頁加上一個「體驗引擎」：

```
src/experience/
├─ engine/
│  ├─ ticker.ts        # 全站只有一個 requestAnimationFrame 迴圈（GSAP ticker）
│  ├─ scroll.ts        # Lenis ⇄ ScrollTrigger 同步
│  ├─ quality.ts       # detect-gpu 分 high／mid／low／reduced 四級
│  ├─ assets.ts        # 依章節距離決定優先序的預載器（影格、影片、模型）
│  └─ stage.ts         # 唯一的 WebGL canvas；各章節註冊自己的場景
├─ chapters/
│  ├─ 00-boot/  01-hero/  02-coffee-chat/  03-voyage/  04-skill-tree/
│  └─ 05-character/  06-ai-native/  07-not/  08-finish/  09-credits/
│     （每章：Chapter.astro［HTML 內容］＋scene.ts［動畫］＋mobile.ts［手機編排］）
└─ hud/                # Speedrun 計時器與 splits
```

- **每章是一個資料夾**，一個人認領一章，PR 有自己的預覽網址。
- **品質分級**：high 啟用全部 WebGL 與影格；mid 降低解析度；low 只用 CSS 漸層和靜態圖；reduced 不播動畫。
- **素材**放在 Cloudflare R2（免費額度足夠），不放 git repo，避免 repo 變得很大。
- **新增工具**：Rive runtime（`@rive-app/canvas`）、Motion（只用在 React 元件內）、ffmpeg 腳本（素材處理，放在 `scripts/media/`）。

## 8. 效能預算

| 項目 | 目標 |
|---|---|
| LCP（手機 4G） | < 2.0 秒 |
| 首屏 JS（gzip） | < 120 KB；Three.js、Rive、影格序列都延遲載入 |
| 首頁總傳輸量 | 桌機 < 15 MB、手機 < 6 MB（大部分是出海章節的影格，且只在捲動到附近才載入） |
| 幀率 | 中階手機 60fps，捲動時不掉幀 |
| CLS | < 0.05 |
| 無障礙 | 鍵盤可操作、減少動態模式、對比 AA、所有內容都是 HTML |

## 9. 時程與分工

| 週 | 里程碑 | 主要負責 |
|---|---|---|
| 1 | 情緒板、分鏡定稿、Seedance 授權與預算確認 | Ray、Sun |
| 1–2 | 體驗引擎、內容層、HUD、Hero（先用 shader，不等影片） | Ray（＋AI 開發） |
| 2 | 定調靜幀、第一批 Seedance 測試 | Sun、Ray |
| 3 | **Launch 版上線**：Hero＋HUD＋終點線＋Credits Roll＋完整內容 | 全員驗收 → 水球發第二波招募 |
| 4–5 | 出海章節（Seedance＋影格捲動）、coffee chat | Ray、Kun |
| 5–6 | 技能樹、角色選擇（Rive）、AI 展示 | Kun、Yapi、Sun |
| 7 | 打磨：微互動、游標、轉場、404、音效（預設關閉） | 全員 |
| 8 | 實機測試、效能調校、**Award 版上線**、決定是否投稿 | 全員 |

時程假設志工每週各投入數小時，程式開發大部分由 Ray 搭配 AI 完成。

## 10. 需要拍板的事

1. **Seedance 經費**：約 60–300 美元，由誰出？還是只用免費額度做較簡單的版本？
2. **投稿**：Awwwards、CSS Design Awards、FWA、紅點都要報名費；要不要投、經費從哪來（不能用收費置入換取，憲法第 7 條）。
3. **美術拍板人**：建議由 Sun 擔任，每個章節的最終畫面都由 Sun 確認。
4. **AI 生成素材是否標示**：建議在頁尾與 Credits Roll 註明。
5. **素材託管**：用誰的 Cloudflare 帳號開 R2。
